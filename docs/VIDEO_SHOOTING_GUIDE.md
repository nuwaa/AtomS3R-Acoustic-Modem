# 2台の音響通信をiPhoneで撮る — 撮影台本

**日本語** | [繁體中文（臺灣）](VIDEO_SHOOTING_GUIDE.zh-TW.md) | [简体中文](VIDEO_SHOOTING_GUIDE.zh-CN.md) | [English](VIDEO_SHOOTING_GUIDE.en.md)

対象は `feature/bell103` ブランチの実機デモ。AX.25/Bell 202（1200 bps）とBell 103（300 bps）を、2台のATOM S3R＋Atomic Echo Baseで別々に撮る。iPhoneは撮影専用とし、Android A・BをそれぞれのATOMのUSBホストにする。これは空中の音による通信で、無線送信機やチャットサーバーは使わない。

```text
Android A ─USB-C─ ATOM A ))) 空中の音 ((( ATOM B ─USB-C─ Android B
                              ↑
                         iPhoneで撮影
```

## 撮影前の準備

1. Android A・Bを各ATOMへUSB-C接続し、両アプリの上部に「ATOM接続済み」（受信中の表示でも可）が出ることを確認する。接続しなければ「詳細」→「USB再接続」を押し、USBアクセスを許可する。
2. 2台のATOMのスピーカーとマイクが互いに聞こえる、これまでの試験と同じ配置に固定する。撮影中は位置・音量を変えない。iPhoneの画角に2台のAndroid画面と2台のATOM本体を入れ、AFSK音と接続音が録れるか10秒の試し撮りで確認する。
3. 両アプリで「詳細」→「通信: 直接」を確認する。必要なら切り替える。「IPトンネル開始」と「受信専用モニター開始」は押さない。前のメッセージの送達待ちが終わってから撮影する。
4. A/Bが分かる紙ラベルを置き、Androidの画面が撮影中に消えないようにする。通知など個人情報が映らない状態を確認する。iPhoneは固定し、基本は音を含む連続撮影にする。

## カット1：AX.25 / Bell 202の双方向チャット

所要時間は再送次第。画面の「直接チャット」と相手の本文を一緒に映す。

| 順番 | 操作 | 撮る確認点 |
| --- | --- | --- |
| 1 | 両アプリが「通信: 直接」になっているところを映す | 2台ともUSB接続済み |
| 2 | Aから `AX25 A01 横浜市` を1通送る | A側の送信音、B側ATOMの表示、Bアプリの本文、Aアプリの「直接チャット送達確認」 |
| 3 | A01の送達確認後、Bから `AX25 B01 繁體中文` を1通送る | B側の送信音、A側ATOMの表示、Aアプリの本文、Bアプリの送達確認 |

一度に連投せず、各送達確認を待ってから次を送る。失敗した場合は原因確認のため表示を撮り、再試行する回はメッセージ番号をA02/B02に変える。

## カット2：Bell 103の接続音と双方向チャット

ケーブルとATOMの配置はカット1のまま。両アプリで前のAX.25送達待ちがないことを確認する。

| 順番 | 操作 | 撮る確認点 |
| --- | --- | --- |
| 1 | Bで「詳細」→「応答」を押す | Bに「Bell 103 · 接続中」または応答待ちが出る |
| 2 | Aで「詳細」→「Bell 103 発呼」を押す | AのATOMから鳴る接続音を途中で切らずに録る |
| 3 | 両画面が「Bell 103 · 接続済み」になるまで待つ | 双方の接続状態。接続音後もハンドシェイクに時間がかかる |
| 4 | Aから `B103 A01 横浜市` を1通送る | Bアプリの本文と、送信側Aの「Bell 103送達確認」 |
| 5 | A01の送達確認後、Bから `B103 B01 繁體中文` を1通送る | Aアプリの本文と、送信側Bの「Bell 103送達確認」 |
| 6 | 両方で「切断」を押す | 「AX.25に戻りました」と「直接チャット」 |
| 7 | 任意：Aから `AX25 復帰 C01` を送る | Bell 103後もAX.25で届く様子 |

Bell 103の本文は短くする。300 bpsなので1通ごとに時間がかかり、ACK待ち中は次を送れない。発呼側の接続音はダイヤルアップ風の再現音で、電話回線との実際のネゴシエーションではない。

## 撮影後にPCで確認する場合（動画本編には不要）

Androidから2台のATOMを外してPCへ接続し、デバイスマネージャーでCOM5・COM6を確認する。番号が異なる場合、以下の `.cmd` はそのままでは使えない。PCチャット、IPトンネル、Serial Monitorを閉じ、リポジトリのルートで次を実行する。同時に同じCOMポートを開かない。

```bat
TEST_AX25_DIRECT_REGRESSION.cmd
TEST_BELL103_AUTO_DATA.cmd
```

前者はAX.25直接チャット、後者はBell 103自動接続・双方向本文・ACKをCOM5/COM6で試す。**Androidに接続したままの撮影中は実行しない。** 既に撮れた映像の代わりに「試験PASS」だけを示すものでもない。

## 教材に付ける説明

- AX.25映像：USBで入力した文字がATOMでフレーム化され、1200 bps Bell 202 AFSKの音になり、相手ATOMが復号する。
- Bell 103映像：発呼・応答で接続を確認した後、300 bps FSKで本文を送る。ACKが返らなければ再送する。
- 「送達確認」は相手ATOMからの音響ACKを意味する。動画では**相手Androidの本文表示も別に映す**。
- Bell 103の本文は本プロジェクト独自の同期・フレーミングとCRCを使う。一般の電話回線用Bell 103モデムとの相互接続は未検証。
- 撮影した配置で動いたことを示す映像であり、距離や騒音が変わっても同じ成功率になるという意味ではない。
